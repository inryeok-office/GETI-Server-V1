# Template: 인라인 리뷰 코멘트

[`docs/ai/code-review.md`](../code-review.md)의 "인라인 코멘트 형식"이 사용하는 Template다. GitHub PR Diff의 정확한 라인에 다는 인라인 코멘트에 사용한다.

## 기본 형식

```markdown
[P1] 권한 검사 없이 다른 사용자의 리소스에 접근할 수 있습니다

현재 `{발생 조건}`에서 `{실제 동작}`이 발생합니다. 이는 `{근거 문서 또는 테스트}`에서 정의한 `{기대 동작}`과 다릅니다.

제안: `{최소 수정 방향}`

근거:
- `{문서, 테스트 또는 코드 경로}`
```

## 작성 규칙

- 첫 줄에 심각도(`[P0]`~`[P3]`)와 문제·영향을 바로 알 수 있는 제목을 쓴다.
- 한 코멘트에는 하나의 문제만 담는다.
- 문제가 발생하는 구체적인 조건과 실제 영향을 설명한다.
- 확인한 근거(문서, 테스트, 코드 경로)만 인용한다. 추측을 근거처럼 쓰지 않는다.
- 수정 방향은 최소 범위로 제안한다. 전체 구현 코드를 대신 작성하지 않는다.
- 칭찬만을 위한 코멘트, "개선하면 좋겠습니다" 같은 모호한 표현을 쓰지 않는다.
- 비밀값, 개인정보, 긴 코드 원문을 그대로 포함하지 않는다.

## 짧은 형식

추가 설명이 필요 없는 단순 문제는 아래처럼 줄여 쓸 수 있다.

```markdown
[P2] `{조건}`에서 `{문제}`가 발생합니다. 제안: `{최소 수정 방향}`
```

## 예시

```markdown
[P1] Company 삭제 요청이 소유권 확인 없이 처리됩니다

현재 `DELETE /api/v1/companies/{id}`는 요청자의 Role만 확인하고 해당 Company를 등록한 사용자인지 확인하지 않습니다. 다른 사용자가 자신의 Company ID 대신 임의의 `id`를 넣으면 타인의 Company를 삭제할 수 있습니다. 이는 API 명세서의 "본인이 등록한 Company만 수정/삭제 가능" 요구사항과 다릅니다.

제안: Service Layer에서 Company의 소유자와 요청자 식별자를 비교하는 검증을 추가합니다.

근거:
- `CompanyController.kt`의 `deleteCompany` (Role 검사만 존재)
- API 명세서 Company Resource "삭제" 항목
```
